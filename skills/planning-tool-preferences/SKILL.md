# Planning-tool preferences

Optional preferences, not authority. Solution and role constraints, approvals
and safety prevail. Where available, `backlog-item-standards` owns item bodies,
BDD and readiness; `backlog-manager` owns authoring/approval workflow and safe
state lifecycle. Otherwise follow solution item standards. Do not copy their
templates or add independent approval/readiness rules.

## Select the tool

Resolve the tracker from repository guidance or the user's request; confirm
material missing context instead of assuming Azure DevOps.

- Azure DevOps Boards only: read [ADO preferences](references/ado.md).
- Other trackers: follow solution conventions and official documentation;
  report missing optional tool-specific guidance. No default ADO routing or
  silently authored adapters.

Extend only when requested, with a scoped reference and an explicit applicable
link here; no registry, resolver or configuration schema.

## Apply sparingly

- Keep updates/comments concise, factual and actionable; no boilerplate or emojis.
  Include useful item links and explain their relevance.
- Solution owns organization/project and custom field, state, area, iteration
  and tag mappings. Never estimate, assign sprints, prioritize or advance states
  on your own authority.
- Use available authorized tools and live schemas, not fixed aliases. Diagnose
  registration, grant or authentication problems only from evidence; report
  missing access, without silent raw-PAT workarounds or settings changes.
  This skill grants no approval.
- Preserve unrelated fields, links and tags. Remove internal drafts/notes from
  outbound content; do not expose sensitive information.
- Re-read outcomes, including partial writes. Report incomplete work rather
  than success; reconcile uncertain outcomes before retrying to avoid duplicate
  writes.
